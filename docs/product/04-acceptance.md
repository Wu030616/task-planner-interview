# 验收案例

规则、决策和文案编号（R、D、S）见[方案](01-solution.md)；任务编号（T）见[任务拆解](03-tasks.md)。

## 怎么观察

| 观察什么 | 怎么看 |
|---|---|
| 模型调用次数 | 服务端日志里 `mock-ai.started` 的条数，一条代表一次计费调用；同一次调用的 `started` 与 `succeeded` 或 `failed` 共用同一个 `callId` |
| 余额 | 数据库 `User.credits`（`wasp db studio` 或 SQL）；页面右上角"剩余额度" |
| 日程数 | 数据库中该用户的 `PlanResult` 条数；页面上的历史日程 |
| 准备数据 | 用 `wasp db studio` 或 SQL 把测试账号余额设为指定值；描述含 `[fail]` 的任务会让模拟接口明确失败（见 [README](../../README.md)） |

## 不变量

每条案例的所有请求结束后，下面三条都要成立：

- I1：余额始终不小于 0，过程中也不能出现负数。
- I2：初始余额减去最终余额，等于新增日程数。
- I3：刷新页面后，右上角余额与数据库一致。

## 单次请求

| ID | 场景 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|---|
| AC-01 | 正常生成 | 余额 3；1 条普通任务 | 点击"生成日程" | `started` 1 条、`succeeded` 1 条；余额 2；新增日程 1；显示日程和 S3 文案，提示剩余 2 个 |
| AC-02 | 余额为 0 时打开页面 | 余额 0；有任务；至少 1 份历史日程 | 打开页面 | 生成按钮置灰；按钮下方显示 S4 文案（暂不支持充值、联系管理员）；历史日程可见；没有发出生成请求 |
| AC-03 | 余额为 0 时请求仍到达服务端 | 余额 0 | 绕过页面直接调用生成接口，模拟页面余额过期 | `started` 0 条；余额 0；新增日程 0；返回 S5 文案 |
| AC-04 | 模型失败 | 余额 3；有一条描述含 `[fail]` 的任务 | 点击"生成日程" | `started` 1 条、`failed` 1 条；余额仍为 3；新增日程 0；显示 S6 文案，不出现英文技术报错 |
| AC-05 | 失败后重试 | 余额 1；有一条描述含 `[fail]` 的任务 | 点击生成；删除含 `[fail]` 的任务；再点击生成 | 第一次：失败，余额仍为 1，显示 S6；第二次：成功，余额 0，显示 S3 |
| AC-06 | 保存失败 | 余额 3；测试环境开启保存失败注入（T9） | 点击"生成日程" | `started` 1 条、`succeeded` 1 条；余额仍为 3；新增日程 0；显示 S7 文案 |

## 并发验证要求

给 T7 的要求：

1. 每次运行前，把测试账号余额设为案例指定值，并记下该账号已有的日程条数。
2. 登录拿到会话，然后同时发出 N 个生成请求。必须真正同时发出，不能一个接一个地发。
3. 收集四项结果：每个请求的结果（成功、没有可用额度或其他错误），这段时间内 `mock-ai.started` 的条数，最终余额，新增日程条数。
4. 逐项与上表比对，输出通过或不通过。
5. 每个案例连续运行至少 3 次，结果完全一致才算通过。
